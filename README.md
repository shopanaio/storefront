## What it is

A storefront template built with Apollo Client and the Next.js application
owned by `@shopana/storefront`. GraphQL operations are external typed
documents generated by the project-wide codegen workflow.

## Requirements

- Node.js ≥ 18.17
- Yarn (recommended)

## Installation

```bash
git clone <your-fork-or-repo-url>
cd storefront-ui
yarn install
yarn --cwd mockServer install
```

## Environment variables (.env)

Copy `.env.sample` to `.env` at the project root and choose one of the options depending on the CMS.

### Shopana

```bash
SHOPANA_GRAPHQL_URL="https://sandbox.shopana.io/api/client/graphql/query"
SHOPANA_API_KEY="your-shopana-api-key"
```

### Shopify

```bash
SHOPIFY_GRAPHQL_URL="https://your-store.myshopify.com/api/2025-07/graphql.json"
SHOPIFY_API_KEY="your-shopify-storefront-access-token"
```

## Generate GraphQL schema and types

The project uses one codegen command for schema types and Apollo operations:

```bash
CMS=shopana npm run codegen
```

Important: the commands read variables from `.env`. Make sure you set correct values for the chosen provider.

Apollo documents use the `*.graphql` suffix. Generated storefront
operations are written to `codegen/apollo/storefront-operations.ts`; SDK
operations are generated inside the SDK source tree.

## Run in development mode

```bash
yarn dev
```

`@shopana/storefront` owns the Next.js dependency and runs its CLI. The
`dev` and `build` commands first generate the App Router application in
`.runtime`; `start` launches an existing `.runtime` build. The generated routes connect the project-owned
`src/layouts`, `src/templates`, and `src/modules` directories. Run the generator
directly after changing its package templates:

```bash
yarn runtime:init
```

Do not edit `.runtime`; customize the root app integration in `src/runtime` and
the page implementation in the corresponding source directories.

The root may replace a runtime default with one explicit override from each
group: `next.config.{js,mjs,ts}`, `middleware.{js,ts}` or `proxy.{js,ts}`,
`instrumentation.{js,ts}`, and `instrumentation-client.{js,ts}`. An override is
a full replacement. Conflicting variants stop generation with a clear error.

Code under `src` imports framework APIs through the runtime facade, for example:

```tsx
import Link from '@shopana/storefront/next/link';
import { usePathname } from '@shopana/storefront/next/navigation';
```

This starts both services for local development:

- the GraphQL mock server at `http://127.0.0.1:4100/graphql`;
- Next.js at `http://localhost:3001`.

The development command sets the mock URL for the shared environment config, so
Apollo sends requests to the local mock. Values from `.env` are not
used for the Shopana GraphQL URL while this command is running.

Use `MOCK_SERVER_HOST` and `MOCK_SERVER_PORT` to override the mock address:

```bash
MOCK_SERVER_PORT=4200 yarn dev
```

The services can also be started separately with `yarn dev:mock` and
`yarn dev:next`. In that case, provide `SHOPANA_GRAPHQL_URL` to the Next.js
process explicitly if it should use the mock server.
