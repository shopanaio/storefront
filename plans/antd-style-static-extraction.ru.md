# Статический CSS из `createStyles` при сборке `brand-bite-crunch`

## Вывод

**Экстрактор с заменой вызовов `useStyles` на готовые классы делать не стоит.** Его выигрыш CPU сверх
полного патча хуков — около 6,5 мс на страницу, меньше 1% (оценка). Почти вся цена `useStyles` сидит
в двух оставшихся копиях темы, а не в вычислении стилей.

**Нужны две другие работы:**

1. **Дополнить патч `antd-style`.** Это снимает почти всю цену хука: с 327 до примерно 7 мкс на вызов.
   Предел выигрыша — доля `antd-style` в профиле, ~39% занятого CPU, плюс часть GC (оценка).
2. **Собирать CSS в файл, не трогая компоненты и вызовы.** При сборке считаем те же правила Emotion,
   кладём их в один файл и заранее отмечаем их как вставленные в кэше Emotion. CPU это почти не
   меняет. Выигрыш другой: из каждого HTML уходит до 463 КБ встроенного CSS.

Невыполнимых условий нет: токены постоянны и известны при сборке. Но замена вызовов упирается в
checkout и `cx`: 104 из 293 функций дают другой CSS под токенами checkout, а в 44 вызовах `cx` стили
перекрывают друг друга. Вариант без замены обходит оба препятствия: имена классов и логика `cx` не
меняются, а всё, чего нет в файле, идёт как сейчас.

Этот план не решает 1000 страниц в секунду: после патча останутся Apollo, `antd` и сам React.

Запуск в Node 22, `NODE_ENV=production`, сборка `lib/` с текущим патчем `a7fa4018`, `renderToString`.
На входе 293 реальные функции без пропсов, по 4 экземпляра, всего 1172 вызова; показана медиана.

## Этапы

**0. Замер на настоящей странице.** Собрать production и запустить на отдельном порту с mock-сервером,
порт 3001 не трогать. Посчитать по маршрутам (главная, каталог, товар, корзина, checkout): число
вызовов `useStyles`, долю `antd-style` в профиле, байты встроенного CSS на холодном и на прогретом
процессе.
*Готово, когда* есть таблица по маршрутам и подтверждено или опровергнуто значение ~1200 вызовов.

**1. Патч хуков.** Завершить дополнение из сессии про две оставшиеся копии: `createUseTheme.js:45` и
`useAntdTheme.js:8`, в `es` и `lib`. Общий для экземпляров кэш по `WeakMap(theme)` добавить, только если
этап 0 покажет больше 1% CPU на вычислении стилей.
*Готово, когда* `antd-style` занимает меньше 3% занятого CPU, а GC снизился.

**2. Прототип на 5–10 самых частых компонентах.** Список взять из счётчика этапа 0, ограничить модули
списком разрешённых. Сделать:

- Плагин Vite только для сборки, подключённый через `vite.config.ts:25`. Он нарезает модули стилей
  разбором AST и выполняет их с настоящими токенами.
- Виртуальные модули с CSS и со списком имён.
- Заполнение `cache.inserted[id] = true` до первого рендера.

*Готово, когда* у выбранных модулей нет встроенных правил, нет предупреждений гидратации, а
`getComputedStyle` на этих компонентах не изменился.

**3. Все функции без пропсов и набор токенов checkout.** Убрать `data:`-узор в файл изображения. Редкие
разделы (ассистент, кабинет) можно не включать: они останутся встроенными, как сейчас.
*Готово, когда* встроенный CSS прогретого процесса упал в разы (порог по этапу 0), а сравнение из
раздела «Проверка» чистое на всех маршрутах и брейкпоинтах.

**4. Защита в CI.** Сборка падает при ошибке выполнения модуля стилей или расхождении токенов.
Отчёт о классах, не попавших в файл, идёт как артефакт.
*Готово, когда* проверка стоит в `ci.yml`, а намеренно сломанный модуль роняет сборку.

**Замену вызовов не делать.** Вернуться к ней стоит только ради полного удаления Emotion и stylis из
клиентского JS. Для этого придётся разобрать 23 функции с пропсами, глобальные стили и все `cx`. Вес
этих библиотек в бандле не измерен, сначала измерить.

## Ответы по токенам

Значения подставлять **реальные, а не `var(--ant-*)`**:

- **Токены постоянны.** `customToken` (`Theme.tsx:20`) и `antdTheme` (`Theme.tsx:36`) — константы модуля
  из `brandConfig` и `theme-tokens.ts`. От магазина, языка и настроек не зависят. `useStore`
  (`Theme.tsx:82`) влияет только на страну телефона. `generalSettings` редактора темы токены не задаёт.
- **`token` и сейчас содержит значения:** 515 ключей, например `colorPrimary: #1c4dcc`. Обратите внимание,
  что `antd` приводит цвет к нижнему регистру, поэтому токены надо получать настоящим рендером
  `ThemeProvider`, а не копировать из конфига. Иначе хэши разойдутся.
- **`var()` здесь хуже.** Он не работает в `@media` и в арифметике (20 функций темы). Кроме того,
  переменные объявлены на классах `.css-var-*`, а не на `:root`.
- **Три значения уже содержат `var()`** (`fontFamily` и два `color-mix`). Они ведут себя как сейчас.

## 19 компонентов с пропсами

Всего таких функций 23: 19 в теме и 4 в пакетах. **Оставить на runtime.**

- **Цена.** После патча примерно 7 мкс на экземпляр (О, по среднему среди функций без пропсов): на 300
  экземпляров около 2 мс. Переводить на CSS-переменные ради CPU смысла нет.
- **Единственный повод для переменных:** пропсы с большим числом разных значений. Каждое значение — новое
  правило, которое остаётся в кэше процесса и уходит в HTML всех следующих запросов (строка 2). Кандидаты:
  `ui-kit/Image/Image.tsx:159` (`ratio`), `ui-kit/Thumbnail/Thumbnail.tsx:131`. Размер проверить этапом 0.

## Проверка

**Вид.** Сейчас в `ci.yml` нет ни Playwright, ни Storybook (К), поэтому проверку надо создать:

1. Собрать «до» и «после» на одних данных из `mockServer`, с отключёнными анимациями.
2. Пройти маршруты на ширинах из `breakpoints.ts`: 375, 576, 768, 1024, 1280, 1440.
3. Сравнить `getComputedStyle` каждого элемента, включая `::before` и `::after`. Это основной критерий.
4. Сравнить скриншоты как второй критерий.
5. Проверить, что каждый класс `acss-*` в DOM есть в файле или во встроенных правилах.
6. Отдельно пройти checkout, потоковые секции и клиентский переход на ленивый маршрут.

**CPU.** Одна production-сборка, отдельный порт, одинаковый поток запросов и `--cpu-prof` в трёх
состояниях: до патча, после патча, после файла. Сравнивать занятый CPU на страницу, долю GC, размер HTML.
Сверх патча по CPU ожидается меньше 1% (О): заметный результат файла будет в байтах HTML и в работе браузера.

## Что подтверждено и что нет

- **Прочитано и измерено:** таблицы выше, метки К и З. Скрипты (AST-разбор, срезы, бенчмарки) остались
  во временном каталоге сессии и в репозиторий не добавлены.

  реальная версия дополненного патча, разбор CSS на телефоне, вес Emotion в бандле.
- **Не прочитано:** `es/factories/createThemeProvider/TokenContainer.js`, доступ к файлу запрещён
  настройками. Сохранение `customToken` во вложенной теме проверено только запуском.
